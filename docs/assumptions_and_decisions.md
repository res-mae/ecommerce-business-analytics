# Assumptions and Decisions

| Date | Question or Issue | Evidence | Decision | Reason |
|---|---|---|---|---|
| 2026-10-12 | How to type `order_date`, `order_time`, and `is_repeat_customer` in the raw sales table | Sample row shows clean values, but only one row was inspected | Load as TEXT. Convert and validate during cleaning. | Raw layer should not fail on unseen bad values. Conversion is a documented cleaning step. |
| 2026-10-12 | How to type columns in raw.dataset_statistics | Full file has one row, all values visible; `$`, `%` and a date-range string appear in some columns | Plain numeric columns typed NUMERIC; columns with `$`, `%` or a range string loaded as TEXT and converted during validation | Numeric typing would fail on symbols; the raw layer should not alter values |
| 2026-10-13 | Should the 87 repeated (order_id, product_id) pairs be removed? | No pair is an exact copy; unit_price is stable; even the closest pair differs by more than 3 in several money columns | Keep all rows in order_items; treat grain as one row per order line, not unique per (order_id, product_id) | Removing rows would delete real differences; cause of repetition is unproven, so revisit if reconciliation against the sales table disagrees |
| 2026-10-13 | How to treat NULL delivery and review fields | All 24,557 non-Completed orders have all five fields NULL; no Completed order does | Do not impute or drop; analyze delivery and ratings on Completed orders only | NULLs reflect order status, not data loss. Revisit if later checks show otherwise |
| 2026-10-14 | Can product_subcategory be used alone for grouping? | 3 of 117 subcategories (Storage, Watches, Furniture) appear under 2 categories each, giving 120 category/subcategory pairs | Always group by product_category and product_subcategory together. Consider a combined key in the analytics layer. | Grouping by subcategory alone would merge products from different categories. Revisit if the model needs a single subcategory key. |
| 2026-10-17 | How to handle `order_date` and `order_time`, which are TEXT in raw | All values match YYYY-MM-DD and HH:MM:SS (0 mismatches). Casts to DATE and TIME succeed for all 138,116 rows. Range is 2021-01-01 to 2025-12-31. | Convert to DATE and TIME in the analytics layer. Keep the raw columns unchanged. | Safe to convert because every value parsed. Raw stays as received, so the conversion is documented and repeatable. |
| 2026-10-17 | Whether to recompute profit excluding tax | profit = net_sales - product_cost - shipping_cost on all rows in both tables, which equals gross_sales - discount_amount + tax_amount - product_cost. So profit includes tax. | Keep profit as given in the analytics layer for now. Add a separate "profit excl. tax" measure only if the analysis needs it. | Source profit reconciles with dataset_statistics, so changing it would break that link. Tax inflating profit is documented as a limitation. |
| 2026-10-17 | How to handle `is_repeat_customer`, which is TEXT in raw | 0 NULLs and 0 blank or placeholder matches. Distinct values skimmed in the categorical check: only 'True' and 'False' | Convert to BOOLEAN in the analytics layer. Keep raw unchanged. | Every value maps cleanly to a boolean, so the conversion loses nothing. Raw stays as received. |
| 2026-10-18 | Whether to round money columns to 2 decimals | Formula gaps are about 1e-12 (floating-point noise). SUM(net_sales) reconciles with the reference revenue both unrounded (gap 0.000000000017505) and with per-row rounding to 2 decimals (gap 0.00). | Round to 2 decimals in the analytics layer: in the sales table `gross_sales`, `discount_amount`, `tax_amount`, `shipping_cost`, `net_sales`, `product_cost`, `profit` and `customer_lifetime_value`, and in `order_items` only `shipping_cost`. Keep `discount_percentage` at full precision. Keep raw unchanged. | Removes floating-point noise for cleaner values and comparisons. Per-row rounding does not change the reconciled totals. |
| 2026-10-18 | How to represent NULL `campaign_name` and `coupon_code` | NULL on 60.3% and 80.0% of rows. No blanks or placeholders. NULL rates are even across marketing channels and independent of each other. `Default_Campaign` is a separate real value. | Keep NULL in raw. In the analytics layer add `has_campaign` and `has_coupon` flags. Keep `Default_Campaign` as its own value. Do not use 'N/A' or 'None'. | NULL means no campaign or no coupon, which is likely but unproven, so no label is invented. Flags are easy to filter and count in DAX. Pandas also reads 'N/A' and 'None' as missing values by default. |
| 2026-10-18 | Which table is the source for order-level measures | sales matches dataset_statistics to the cent. order_items totals run about 8.6% higher, driven by 11,226 orders where order_items quantity exceeds the sales quantity. | Use the sales table for order-level measures. Use order_items only for product-level analysis, and never sum both. | Only the sales table reconciles with the reference totals. Revisit if the cause of the gap is found. |
| 2026-10-18 | How to count customers given 89 customers with no orders | customer_master has 25,000 customers. The sales table has 24,911 distinct customers, matching dataset_statistics. | Count active customers from the sales table. Use customer_master for attributes only. | Counting from customer_master would not match the reference total, and the 89 would show blank measures. |
| 2026-10-18 | Whether to round `discount_percentage` | Up to 16 decimals in 343,632 rows. Rounding to 2 decimals breaks the discount formula on 341,223 rows (85.8%) | Keep full precision. Format as a percentage in Power BI | Rounding changes the data and breaks a verified relationship. Display formatting is enough |
| 2026-10-29 | Which financial measures to use in business analysis | `analytics.sales` Net Sales and Profit totals reconcile with `dataset_statistics` to the cent. The source has no data dictionary. The recorded formulas show that `profit` includes `tax_amount`. | Use `analytics.sales.net_sales` as the primary order-level Net Sales measure and `analytics.sales.profit` as the primary Profit measure. Treat both as dataset-defined measures, not independently verified accounting figures. | These measures preserve consistency with the dataset's reference totals. Their business and accounting definitions are not fully documented. |
| 2026-10-29 | Whether to include all order statuses in the initial financial comparison | Q1 shows recorded Net Sales and Profit for Completed, Returned, Cancelled, and Pending orders. Together, the four statuses account for 100% of recorded Net Sales. | Include all statuses in Q1 and report each status's share of total recorded Net Sales. For subsequent analyses, choose statuses according to the business question and state the scope explicitly. Use Completed orders for delivery and rating analyses. | Including all statuses provides a complete view of recorded values. However, amounts for Returned, Cancelled, and Pending orders cannot automatically be interpreted as realized revenue or retained profit. |
